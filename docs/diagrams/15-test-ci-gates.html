Architecture · funes-vision

What has to be green before a change lands

Two CI jobs, both on every push and pull request. The fast job is pure text and pure Python — no browser, no package.json. The second job is a headless-Chromium accessibility and visual gate that is deliberately isolated, because it is the only thing in this repo that can see what a human actually sees.

Why the browser gate is its own job

  • It downloads ~170 MB and takes ~30 s, so it is split out so a flake there cannot block the fast suites.
  • It runs against synthetic fixtures, so a CI run can never touch real footage.
  • Before it is allowed to gate anything, --selfcheck proves it is not vacuous: a 6 px target, 3.45:1 text, a 2000 px block, an <img> with no alt, a refused request and an uncaught exception must all fail; a 700 ms spin must fail under reduced motion.

Reading the fast column

  • The Node suites never launch a browser. They extract a pure:NAME block from index.html and eval it — see 14-frontend-internals.
  • Because every lookup in tests/helpers/load.cjs throws on a miss, a “this pattern is absent” assertion can never pass vacuously on an empty string.
