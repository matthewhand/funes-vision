Which files ship, and who decides

One page asks for its static assets by name. Four unrelated places decide what actually gets copied to a web root, a demo bundle or a test stub. Miss one and the page still works in the other three, so nothing complains — which is why one test exists purely to diff them.

Why this bites during the split

  • Moving markup into js/*.js and css/*.css adds new src/href values, so the asset set grows.
  • Each new file has to be added to all four lists in the same commit. Three out of four still looks fine on screen.
  • The failure is silent by construction: a missing file 404s in exactly one target and nowhere else, so no other test sees it.

The one deviation on record

  • tools/demo/build_demo.py ships no USER-GUIDE.html, so the gallery's Help link 404s in the published demo. The demo sets window.__IS_DEMO__ but the SPA never reads it, so the link stays live.
  • It is recorded as a named KNOWN_GAPS entry rather than dropped, so the assertion fails if the entry ever goes stale.

Two lists, not one

  • tools/deploy-webroot.sh keeps ASSETS[] and OPTIONAL_ASSETS[] apart and copies with basename(), which is what flattens docs/USER-GUIDE.html to the image root.
  • Any asset not in the manifest map has to reach all four lists; anything in it must match exactly.
