Inside index.html: the A–S section map

The SPA is one inline classic <script> (lines 3126–8944, 281,628 bytes, 197 function declarations). The hand-maintained comment block at the top of the file names it A–S; this diagram groups those 19 letters by concern so you know which group to open before you start editing.

Start here: the pure helpers

  • Sections C, G and K are the only ones whose functions are pure, and each is wrapped in a // === pure:NAME === … // === /pure:NAME === pair — 95 pairs today.
  • A suite pulls the exact block out of index.html and evals it, so the page and the unit test share one copy of the function.
  • That contract is why the planned js/*.js split is tractable: a pure helper is already a self-contained unit with a test attached.

Three kinds of section, not two

  • Pure — sentinel-wrapped, no state, no DOM. Unit-tested without a browser.
  • Impure — the map flags these explicitly (the labelStates currying helpers, the focus-trap and popover machinery, computeVisits). They read state or the DOM, so they have no sentinel and are covered by text assertions instead.
  • Bootstrap — D plus Q/R/S. Q, R and S are three slices of one DOMContentLoaded arrow function, not three scopes.

What this diagram leaves out

  • The ~85 KB <style> block (lines 139–2674) — CSS, not client logic.
  • Individual function names. The map in index.html:2–121 has them; listing 197 here would be a table, not a diagram.
  • js/ does not exist yet. This is today's file, not the target layout.
